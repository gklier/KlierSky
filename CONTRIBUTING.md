# Contributing

Start with a focused issue describing the user problem, expected behavior and relevant source/provider. For fixes, keep changes small and include validation that demonstrates the behavior. Run `sh Tests/run.sh` for model/gateway changes and build the app and widget targets for SwiftUI changes.

Use Apple system typography and original assets. Preserve compact layout, source attribution, missing values, observation/forecast boundaries and honest uncertainty. Never put vendor keys, gateway tokens, pairing state, signing profiles, private logs or device data in commits, screenshots or issues.

Provider access and redistribution rights must be verified before integrating new weather products. Do not turn observed radar into futurecast or infer precision beyond a provider's actual resolution.

Keep the README, `Docs/` and screenshots current with every finished change. Screenshots must be real captures from the app; if one is out of date, say so beside it.
